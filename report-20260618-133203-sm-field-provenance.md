## Task 4 — Implication

### What the custom-search tier-2 path ACTUALLY reads

The custom-search endpoint (server.ts:4399) calls `fetchAnimals()`, which returns `animal.description = raw.ANIMALCOMMENTS`. It does **not** call `resolveBioText()`. Therefore:

**The custom-search tier-2 path reads the SHORT SM ANIMALCOMMENTS note, not the long AI-generated bio.** [VERIFIED]

### What the verification harness read

My verification harness (`trait-summary-harness.mjs`) called `GET /api/animals`, which returns the `resolveBioText()`-resolved description. For Lucky and Munster, this returned the approved AI bio instead of the raw ANIMALCOMMENTS. **The harness was reading the wrong field.** [VERIFIED]

|---|---|---|---|---|

| **Munster** | `"Not meant to be a household pet, but would be a great barn cat."` (63 chars) | ✅ Yes (approved, 659 chars) | AI bio (659 chars) | ⚠️ **YES** |

### What this means for the tier-2 builder

When `buildTraitSummary()` is actually wired into the custom-search endpoint, it will receive `animal.description` from `fetchAnimals()`, which is the **raw ANIMALCOMMENTS**. So:

- **Lucky:** will get `"Shelter note: Not meant to be a household pet, but would be a great barn cat."` (77 chars) — the SHORT note, not the AI bio. This is actually **correct** — the short note carries the real placement signal. [VERIFIED]
- **Munster:** will get the same `"Shelter note: Not meant to be a household pet, but would be a great barn cat."` (77 chars) — also correct, same SM ANIMALCOMMENTS. [VERIFIED]
- **Blizzard:** same as above, no change. [VERIFIED]
- **Iron:** 268-char SM note, truncated to 200-char budget. [VERIFIED]

### The harness results were misleading but the production path is correct

The harness showed Lucky (207 chars of AI-generated "Meet Lucky...") and Munster (211 chars of AI-generated "Meet Munster...") because it fetched from `/api/animals`. In production, the custom-search endpoint gets `fetchAnimals()` directly, which returns the raw ANIMALCOMMENTS — the short barn-cat notes. **The tier-2 builder will produce the correct, short output in production.** [VERIFIED]

### Additional observation

Lucky, Blizzard, and Munster all have the **exact same** ANIMALCOMMENTS: `"Not meant to be a household pet, but would be a great barn cat."` This is likely a copy-paste or template applied to all barn-cat placements. In production, three cats will have identical tier-2 lines. This is fine — they genuinely have the same placement signal. [VERIFIED]

### Where the short note lives (for reference)

If the custom-search endpoint ever needs to read the approved AI bio instead of the raw ANIMALCOMMENTS, it would need to call `getAnimalBio(shelterCode)` from `localDatabase.ts` and apply `resolveBioText()`. Currently it does not, and for the tier-2 compact-summary purpose, the raw ANIMALCOMMENTS is the **better** source — it's the operator-entered factual note, not marketing prose. [INFERRED]
